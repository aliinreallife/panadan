### Database and service

- database/migrations/006_knowledge_rls.sql is additive and requires explicit owned PG18 target, administrator, 004/005 foundation and the restricted existing owner. Creates two NOLOGIN/NOINHERIT/NOSUPERUSER/NOBYPASSRLS capability roles: panadan_knowledge_authorizer and panadan_knowledge_reader. No runtime login or memberships are provisioned by migration. Conflicting privileged roles or existing role memberships cause refusal; replay tested before login provisioning, not a production repair procedure. Migration 004 and 005 unchanged.
- Forced RLS extends to the two global registry tables; memberships, role_versions, membership_roles and scope_grants use candidate workspace RLS, including write checks. Authorizer registry lookup is limited to the verified principal, members of the candidate workspace and an explicit same-authority enrollment target. Existing add_member sets that target only inside the authorized operation and clears it before return. Reader can only select the fixed workspace projection after current workspace.read authorization and with a matching policy epoch. Policy definitions remain inaccessible; audit is insert-only for matching actor/workspace/epoch, web/succeeded and empty metadata; neither role receives deletion/truncate, schema CREATE, principal mutation, audit read or legacy schema grants. Invalid/missing UUID context resolves to NULL; no SECURITY DEFINER functions or BYPASSRLS roles added.
- server/knowledge_scope.py provides an opt-in, synthetic-only ScopedWorkspace boundary. Caller must supply a dedicated idle autocommit PG18 panadan_ci connection with a restricted login, exact non-inherited SET ROLE membership in both capability roles, no direct knowledge schema access, owner membership or privileged flags. Extra or inherited role membership and dirty scope are rejected. No production connection factory, startup hook or HTTP endpoint. Before and after each transaction the boundary checks role/context cleanliness; contaminated idle connections are closed; active caller transactions are rejected without committing or rolling back caller work.
- Uses READ COMMITTED, transaction-local role, row_security=on, pinned search_path, bounded statement/lock waits and six transaction-local settings. Candidate scope is established from current verified SQLite session and requested workspace solely for internal authorization resolution. Workspace selection is not proof of access. M01.2 service then checks active identity/membership, pinned roles and current explicit scope grants while locking workspace. Only fixed allowlisted operations are exposed, no arbitrary SQL/callback API. Read projection uses separate reader role and matching policy epoch, repeats current authorization before return. All operations recheck session before commit; no cross-store atomicity claim. The workspace row lock serializes service-managed mutation and authorization; a waiter at READ COMMITTED must read committed grants after the lock is released. SET LOCAL unwinds on commit/rollback; residual context closes connection. If cleanup fails after a successful commit the caller must reconcile rather than blindly retry.
- Trust boundary: RLS protects against accidental missing tenant predicates, not arbitrary SQL executed as a trusted role or compromise of database credentials. Candidate authorizer scope can see scoped policy rows for resolution; never expose them directly. Reader cannot inspect membership/role/policy tables. Source/operator data, service identities, scheduler, worker, client and external disclosure access remain denied and will require their own reviewed roles and scoped operations as implemented. Existing unscoped M01.2 service is internal only, not a runtime entry point. No production role/ACL inventory, identity restore, login provisioning, physical pool library or live routes added; reusable connection boundary is exercised by tests instead.
